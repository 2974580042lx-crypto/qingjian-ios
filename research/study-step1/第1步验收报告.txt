Sermo 聊天学习第 1 步验收报告
日期 2026-11-10
状态 第 1 步验证完成，等待用户验收。第 2 步待开始。

本步结论

DeepSeek Flash 已通过真实接口验证，可以提出读取资料、保存带出处记忆和纠正记忆的操作，由应用侧校验后执行。
原生工具调用与普通文本 JSON 操作方案都通过了这组短测试。
推荐 DeepSeek 优先复用原生工具调用。ChatGPT 订阅以现有文本请求作为结构化操作的候选接入方式，仍需账号实测。Colab 当前旧地址返回 HTTP 404，操作能力待实例可用时验证。

验证边界

本步使用电脑端 Python 隔离验证器和独立 SQLite 测试库。测试请求采用现有 Sermo DeepSeek 通道对应的模型名、SSE、关闭思考和 Chat Completions 格式。
结果证明这组短对话的服务端协议和隔离执行逻辑可用。iOS 客户端接入、真机恢复、长期检索、自动提取语义质量和多模型一致性还需要后续步骤实现与验证。
本步采用已知测试意图限定每轮允许的操作和出处消息。开放聊天中的意图判定和授权映射属于后续实现，不能把本步结果当成该能力已经完成。

二 真实测试过程

第一个用户请求
请读一下测试资料《词义练习》，我想看 adapt 和 adopt 的区别。

模型操作
study_read_material，参数 material_id 为 sample-vocabulary-1。

应用结果
读取固定的自编测试资料并返回原文。该资料不包含个人聊天或真题。

第二个用户请求
我容易把 adapt 和 adopt 搞混，把这个易混点记到本周总结里。

模型操作
study_remember，附带记忆内容、user-2 消息 ID 和逐字原话。

应用结果
校验原话，事务提交一条记忆，返回 committed，版本 1。操作记录和修改历史同时写入测试库。

第三个用户请求
更正一下，刚才我说错了。我其实容易混淆的是 affect 和 effect。请改正刚才那条记录。

模型操作
study_correct，引用刚才的记忆 ID、expected_revision 为 1、user-3 消息 ID 与更正原话。

应用结果
更新为 affect/effect 的混淆记录，版本升为 2，旧版本保存于事件历史。

两种协议的测试进程结束后，重新打开数据库复核。
每个测试库均为 1 条当前记忆、版本 2、2 条修改事件、3 条操作记录。
完整的模型返回、数据库执行回执、更新前后记录保存在 evidence/live-deepseek-20261110-01/transcript.json。

三 调用量和延迟

真实 DeepSeek 请求共 12 次。每种方式三项操作，每项包含操作提议和执行回执后的文字回答，共 6 次请求。
API 返回输入 Token 合计 9511，输出 Token 合计 877，总计 10388。
原生工具每项操作的两次模型请求总耗时约 2.97 至 3.28 秒。
普通文本 JSON 每项约 2.08 至 2.61 秒。
这是一次短样本观察，不能推定长对话、不同模型、不同负载或开启思考后的性能。
本步没有使用额外服务商或辅助模型。

四 已完成的本地检查

16 项自动检查通过，其中包含两个其他项目的访问检查。
- 资料原文读取。
- 保存、更正与重新打开数据库。
- 相同操作重试返回同一回执。
- 同一个操作 ID 携带不同内容时拒绝。

- 其他项目无法读取测试资料或纠正英语记忆。
- 模型无法通过参数覆盖项目或项目指令。
- 伪造出处、错误来源消息拒绝。
- 只读场景提交写操作时拒绝。
- 模拟持久化失败后，记忆、历史与回执一起回滚。
- 重复 JSON 键、非法数值与 Markdown 包装拒绝。
- SSE 分片工具参数正确拼接。
- 中途断开的流无法执行操作。
- “已经记住了”普通文本不会被识别为保存命令。
- 未知操作与布尔类型的版本号拒绝。

五 本步发现及正式实现要求

1. 模型自然语言会泄露内部记录 ID，并可能把一条待整理记忆称为“已记入本周总结”。测试库实际只保存了记忆与修改历史，周报尚未生成。正式界面的保存回执应由应用根据已提交结果生成，并明确区分已记录、待整理和周报已生成。
2. 来源逐字匹配可以证明原话存在，无法单独证明模型概括的含义完全准确。测试中原生工具把词义和例句一起放入易混记录。正式实现需要区分用户学习事实与资料知识，保留各自出处。
3. 普通文本 JSON 本步依靠指令生成，未开启服务端 JSON 模式或严格 schema 保证。完整接收与严格校验后才能执行。解析失败时保留待处理状态，修复重试设置次数上限并记录费用。
4. 记忆操作请求可能增加一次或多次模型交互。正式实现应按需要触发操作，复用本地查找与应用回执，分别记录调用量。
5. Sermo 现有 ChatThread 没有独立服务商和模型选择字段。provider(for:) 从项目或全局设置取值，setProvider 会改项目设置。后续需要为对话保存选择，并使项目默认值只影响新对话。
6. 旧对话迁移应按升级时原项目和设置计算有效选择并保存。导入旧备份时采用备份中的项目与设置，避免被当前全局设置意外改变。
